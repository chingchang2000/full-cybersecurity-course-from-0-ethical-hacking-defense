The course

Lesson 01 · Week 1

Computer and technology basics

Understand computer parts, operating systems, apps, the internet, basic privacy, phishing, and ways to protect your computer.

1 hour
Video: Computer & Technology Basics Course for Absolute Beginners · freeCodeCamp.org
Task 1 · Make a security inventory

On your own computer, find and write down:

  1. Your operating system and whether updates are enabled.
  2. Where your important files are backed up.
  3. Whether your main account uses a unique password and MFA.
  4. One security setting you checked or improved.
Deliverable: a short inventory. Do not include passwords or private account details.
Lesson 02 · Week 2

How the internet and networks work

Learn about routers, switches, IP addresses, packets, internet providers, and how computers communicate.

2 hours
Video: How does the internet work? (Full Course) · freeCodeCamp.org
Task 2 · Draw a network map

Draw how a request from your own computer reaches a website. Include your device, Wi-Fi router, internet provider, DNS, and the website’s server. Add one sentence describing what an IP address does and what DNS does.

Deliverable: a labelled diagram and two short explanations.
Lesson 03 · Weeks 3–5

Linux foundations

Get comfortable with the Linux desktop, terminal, files, permissions, users, processes, and basic system administration.

6h 8m
Video: Introduction to Linux – Full Course for Beginners · freeCodeCamp.org
Task 3 · Linux command practice

In a Linux virtual machine or a permitted online Linux practice environment, create a folder called cyber-course. Inside it, create a notes file. Practise listing files, moving between folders, reading the file, and checking its permissions. Use only files you created for this task.

Deliverable: a short command log with one sentence explaining each command.
Lesson 04 · Weeks 6–7

Python programming basics

Learn variables, data types, conditions, loops, functions, lists, dictionaries, errors, and small projects.

4h 40m
Video: Python for Beginners – Full Course · freeCodeCamp.org
Task 4 · Build a local file checker

Write a Python program that asks for a folder path you control and lists the filenames inside it. Add a check that tells you if a filename you choose exists. Keep it local: do not make it contact websites, scan networks, or collect anyone else’s information.

Deliverable: your script and a screenshot showing it run on a test folder.
Lesson 05 · Weeks 8–11

Cybersecurity and defense

Learn practical ways to protect accounts, data, systems, software, and privacy, while thinking about risk and the value of safeguards.

8 hours
Video: Harvard CS50’s Introduction to Cybersecurity – Full University Course · freeCodeCamp.org
Task 5 · Threat-model a pretend small website

Imagine a small website stores users’ email addresses and passwords. List three things worth protecting, three ways they could be put at risk, and one defense for each. Include MFA for administrators, secure password storage, updates, backups, and a way to notice suspicious activity where relevant.

Deliverable: a one-page risk table. Use fictional data only.
Lesson 06 · Weeks 12–13

Hands-on ethical cybersecurity

See how Linux security tools, network concepts, vulnerability checks, and defensive analysis fit together. Treat its practical sections as demonstrations for authorized lab environments only.

4 hours
Video: Hands-On Cybersecurity and Ethical Hacking – Full Course · freeCodeCamp.org
Task 6 · Write a safe test plan

Before touching a practice target, write a scope sheet: name the lab target, list what you are allowed to test, list what is out of scope, set a stop condition, and state how you will record and report a finding. Practise only in the video’s authorized lab or another platform-provided lab.

Deliverable: a one-page test plan. Never point tools at public or third-party systems.
Final project · the big one

Secure a small home lab

Build a security improvement report for a computer or intentionally vulnerable training machine that you control. Your goal is to make it safer, verify the changes, and explain the result clearly. Keep the test environment private and authorized.

01 · Set the scope

Choose one machine or platform-provided lab. Record its owner, purpose, what you may test, and what is off-limits. Take a clean snapshot or backup before changes.

02 · Record the starting point

Make an asset list and a simple diagram. Record current updates, account protections, exposed services shown by the system’s own settings, and backup status. Do not probe outside your lab.

03 · Identify risks

Pick three realistic risks. For each, explain the possible impact and likelihood in plain language. Prioritize the risk that could cause the most harm.

04 · Improve defenses

Apply safe fixes such as installing updates, removing unused software, enabling MFA, using standard-user access, configuring the firewall, and checking a backup can be restored.

05 · Verify and respond

Repeat your checks and record what changed. Write a short incident checklist for a suspicious login or malware alert: who to tell, how to isolate safely, and how to recover from a clean backup.

06 · Present your report

Include scope, starting state, three findings, evidence with secrets removed, fixes, retest results, remaining risks, and a short summary for a non-technical reader.

Finish line: a diagram, risk table, safe test plan, change log, retest notes, incident checklist, and a 1–2 page report. Do not include passwords, personal data, or details about systems you do not own.
